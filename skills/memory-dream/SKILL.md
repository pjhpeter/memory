整理一个项目的共用记忆库。规则（位置、格式、`agent` 标签）以 `~/.agents/rules/topics/11-memory.md` 为准，先读它。

原则：**副本上整理，核对通过后直接替换原件、提交并推送，无需逐次确认**（用户于 2026-11-17 授权，适用于手动和定时执行）。此授权只覆盖记忆库整理；把记忆升格为规则或 skill 仍需单独确认。`~/.agents/memory/` 是 git 仓库，替换后提交并推送，回滚靠 git，不再复制备份目录。

## 步骤

1. **上锁**。先 `git -C ~/.agents/memory pull --rebase`，并确认 `git -C ~/.agents/memory status --porcelain -- <项目>` 为空（有别人未提交的改动，先按 11-memory.md「Git 同步」提交推送）。目标目录 `M=~/.agents/memory/<项目>`。若 `$M/.dream.lock` 已存在，停下告诉用户有别的整理在进行；否则写入锁文件（内容：Agent 名 + 时间 + 当前 `git -C ~/.agents/memory rev-parse HEAD`）。完成标准：锁文件是你写的。

2. **建副本**。`S=<你的临时目录>/memory-dream-<项目>-<日期>`，`cp -a "$M/." "$S/"`，删掉副本里的 `.dream.lock`。之后所有修改只发生在 `$S`。

3. **摸底**。读 `$S/MEMORY.md` 和每一个条目文件。完成标准：每个条目都读过，并且找出了：索引里有但文件不存在的、文件存在但索引没登记的。

4. **核对事实**。对每条提到具体文件、函数、命令、分支、issue 状态的记忆，用一次低成本查询（`ls`、`rg`、`git log -1`、`glab issue view`）核对它是否仍然成立。查不了的保持原样，标注「未核对」。不扫各家 Agent 的会话记录。

5. **整理**（只改 `$S`），逐条判定为下面一种：
   - **保留**：仍然成立、不重复。
   - **合并**：和另一条讲同一件事 → 内容并进较完整的那条，删另一条，`[[name]]` 引用改指保留的那条。
   - **改写**：相对日期改绝对日期；过时的细节删掉，保留仍有效的 Why / How to apply。按规则里「记什么、不记什么」瘦身：看代码、git、issue 就能知道的现状和逐日进度流水账删掉，只留结论、原因和「去哪里看最新状态」。
   - **删除**：被推翻的、对应代码/专题已不存在且无历史价值的；全局规则、仓库 `AGENTS.md` 或某个 skill 已经写明同一件事的（理由写「规则已覆盖」并指出是哪一处）。已收官但有回查价值的，挪进归档索引条目而不是删除。
   - **提议升格**：规则里还没有，但已经稳定、多次用到、不依赖某个进行中专题的条目。所有任务都要守的 → 提议写进 `~/.agents/rules/`（全局）或仓库 `AGENTS.md`（只和该仓库有关）；某类任务的固定流程 → 提议写进对应 skill。副本里先原样保留，不要自己改规则或 skill。
   - 用户明确说过要保留的、带决策依据的 `feedback` 类条目，只合并不删除。
   - 动过的条目按规则里「写明是谁写的」更新作者字段（`updated_by` 换成自己，`created_by` 不动）。
   完成标准：每个条目都有一个判定。

6. **重建索引**。`$S/MEMORY.md` 每个存活条目一行、不超过 200 行，没有指向不存在文件的行。

7. **核对改动清单**。运行 `diff -ru "$M" "$S"`（排除 `.dream.lock`），逐项核对删除理由、合并后的信息是否完整、改写是否有依据、未核对内容是否保留，以及条目数和索引行数。普通整理核对通过后直接继续第 8 步，不停下等待用户确认。升格提议单独列出条目、目标文件和拟写入原文，保留对应记忆，等待用户单独确认；不阻塞其余整理。获得升格授权后再按规则或 skill 编辑流程写入，验证后删除对应的重复记忆。

8. **替换原件并推送**。先确认原件在整理期间没被改过：`git -C ~/.agents/memory status --porcelain -- <项目>` 为空，且 `git -C ~/.agents/memory log --oneline <锁文件里的 SHA>..HEAD -- <项目>` 为空（别的 Agent 写记忆会直接提交），否则保留副本并停止覆盖，报告并发变化；不得覆盖他人的更新。再同步：`rsync -a --delete --exclude .dream.lock "$S/" "$M/"`。同步到目录内部，不要删除或移动 `$M` 目录本身（Claude Code 的软链接指向它）。然后提交推送：`cd ~/.agents/memory && git add -A -- <项目> && git commit -m "memory(<项目>): dream 整理" && git pull --rebase && git push`（`-A` 只限该项目目录，锁文件不得入库）。无差异也要提交：`git commit --allow-empty -m "memory(<项目>): dream 整理"`。到期提醒（`memory-context.py`）只认这条一字不差的提交信息来判断上次整理时间，不提交或写法不同，提醒会一直出现。推送失败保留本地提交和副本，如实汇报，不强制推送。完成标准：`diff -ru` 只剩 `.dream.lock` 的差异，且 `git status -sb` 显示与 `origin/main` 一致。

9. **解锁并汇报**。成功后删除自己持有的 `$M/.dream.lock` 和副本 `$S`，简报改动、未核对项和这次整理的提交 SHA（要回滚就 `git revert <SHA>` 再推送）。用户取消或中途出错时，同样释放自己持有的锁；失败副本保留用于恢复。
